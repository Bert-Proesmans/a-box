# a-box

NixOS host configuration repository, no `flake.nix` — dependency pinning
goes through the `lon` CLI instead. Also an Obsidian vault rooted here; see
[[AGENTS]] for vault-interaction rules.

## Nix files (repo root)
- `lon.nix` / `lon.lock` - generated by [lon](https://github.com/nikstur/lon).
  `lon.lock` is the source-of-truth lockfile (`nixos`, `nixpkgs`, `disko`,
  `preservation`, `obsidian-mcp` pins); `lon.nix` is the generated fetcher
  wrapping it - not hand-edited.
- `llm-host.nix` - the actual NixOS host configuration. Builds a
  `nixosSystem` by hand (imports `nixos/lib/eval-config.nix` directly, no
  flake) and exposes three outputs:
  - `.system` - the deployed `llm-host`: base identity/network/SSH,
    disko-managed btrfs storage (`@nix`/`@persistent` subvolumes + a
    zram-backed ephemeral root wiped every boot), KVM kernel modules,
    mDNS/DNS-SD advertisement, users, and the `claude-code`/`obsidian-mcp`
    system packages.
  - `.installer` - a minimal installer ISO reusing the same `self`; embeds
    `.system.config.system.build.toplevel` and a `quick-install`
    disko+nixos-install script.
  - `.platformMemoryPostureTest` - `agent-vm-host-platform-test.nix`'s
    `nixosTest`, built against `.system.pkgs`.
- `agent-vm-host-platform.nix` - NixOS module for agent-vm-host chunks 2-4
  ([[02-host-platform]]): dedicated `vm-launcher` user for unprivileged
  `/dev/kvm`, a cgroup-v2 assertion guard, explicit swap/KSM pins, and the
  `agent-vm-host-preflight` boot-time check + systemd service. Imported by
  `llm-host.nix`.
- `agent-vm-host-platform-test.nix` - `nixosTest` (`lib.nixos.runTest`)
  proving chunk 4's memory-posture guard: stock boot reports swap/KSM both
  healthy, then a forced swap device and forced KSM each produce their own
  distinct `FAIL:` message. Scoped to memory posture only, not KVM/cgroup
  v2. Exposed as `llm-host.nix`'s `.platformMemoryPostureTest`; run with
  `nix-build --no-out-link -E 'let self = import ./llm-host.nix {}; in
  self.platformMemoryPostureTest'`.

  Not run to a green result on this deployment - `llm-host` itself runs as
  a Hyper-V guest (Windows 11 26100.9457), so the test's nested QEMU/KVM
  guest is double-nested. Confirmed root cause: `cat
  /sys/module/kvm_intel/parameters/enable_apicv` is `N` - Hyper-V's
  nested-virt does not advertise the VMX secondary execution controls APIC
  virtualization needs, and KVM silently clamps `enable_apicv` off
  regardless of an explicit `enable_apicv=1` modprobe override (verified;
  not a policy tied to `enlightened_vmcs`, which does take the override).
  Tried and ruled out, in order: `virtualisation.useNixStoreImage = true`
  + `virtualisation.sharedDirectories = lib.mkForce { }` (eliminates
  virtiofsd entirely - confirmed working, not the blocker);
  `kernel_irqchip=split` (fixes a real guest clock-corruption artifact at
  ACPI GPE setup, but boot still stalls there); `kernel_irqchip=off` (would
  drop the APICv dependency entirely, but this KVM instance refuses it
  outright: `KVM does not support userspace APIC`). No Hyper-V setting
  (`Set-VMProcessor -ExposeVirtualizationExtensions`, static vs. dynamic
  memory) or NixOS kernel/module parameter changes this - it's a hard
  capability ceiling of Hyper-V's nested-virt feature set on this host.
  Run it on bare-metal KVM (no Hyper-V hop) to actually clear
  `multi-user.target`.
- `systemd-dnssd.nix` - reusable NixOS module adding the
  `systemd.dnssd.services.*` option, rendering mDNS/DNS-SD service files
  under `/etc/systemd/dnssd/`. Vendored from an external source (see the
  file's own top comment). Used by `llm-host.nix` for SSH mDNS
  advertisement.
- `obsidian-mcp.nix` - package derivation (not a NixOS module) for the
  `obsidian-mcp` MCP server binary this vault's `.mcp.json` runs. Built via
  `pkgs.callPackage` from `llm-host.nix`'s `environment.systemPackages`;
  bundles a pre-fetched HuggingFace embedding-model cache so embeddings
  work offline.
